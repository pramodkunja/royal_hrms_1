# Task 110 — Interviewer dropdown, Leave Request cards, Attendance calendar

Evidence is render/mocked-API only (no device or emulator pass, no production calls). Screenshots: `evidence/t110/` (`before_t110_*` / `t110_*`; `i_` interviewer, `lv_` leave cards, `c_` calendar). The "before" shots are the previous interviewer control (rendered standalone: the picker is still used by Separation), the previous leave list (rendered before the edit) and the previous attendance tab (rendered from a backup copy).

## 1. Web → mobile parity findings
**Interviewer.** Web (`AddCandidateModal.tsx` / `EditCandidateModal.tsx`): a plain `<select>` fed by `GET /employees/?page_size=200` — the role-scoped employee directory; there is **no** separate "eligible interviewer" endpoint — option label "name (employee id)", value = the user's real `uuid` (the candidate's `interviewer` is a foreign key to the user), empty option "— Select interviewer —" → `null`. Mobile already sent the uuid; the difference was a search-first picker (nothing visible until typing).
**Leave Requests** (agent-verified against `LeaveTab.tsx`, `LeaveRequestDetailModal`, `LeaveRequestListCreateView`): `GET /leave/requests/?employee_id&year&page` (needs `employees.view` or `leave.approve`); the only web filter is the year; Prev/Next paging (20 per page); rows carry L1/L2 approver, status, remarks, LOP, reason, `can_approve` / `can_cancel`. Mobile showed the raw status (`l2_pending`), no reason, a half day as "1d" and collapsed L1/L2 into one line.
**Attendance** (`useEmployeeAttendance` → `GET /attendance/{stats,summary,calendar}/?employee_id&month&year`; shared `CalendarAndHistory` / `AttendanceCalendar`, read-only): each day record = `status`, `color` (backend hex), `clockIn`, `clockOut`, `hours`, `note`, `holiday_name`, `canRegularize`, `canExplainLate`, `lateJustificationStatus`. `clockIn`/`clockOut` are **plain "HH:MM" strings** (`AttendanceRecord.first_punch_in` / `last_punch_out` are `TimeField`s) — no date, no timezone. Web cells show the times and hide them on Weekly Off / Holiday; Regularize/Explain are hidden in the employee view.

## 2. Interviewer selector (Part A)
New `InterviewerSelectField`: rounded full-width field (name wraps whole; employee id · designation · department beneath, two lines max in the field) → a scrollable sheet that **lists everyone immediately**. "No interviewer" row (web's empty option), selected tick, ≥56dp rows, optional filter (shown for >7 people or when the directory is larger than one page; when it is, the filter also searches the server so nobody beyond the first 200 is out of reach), loading, empty, failure with Retry (403 → the server's message, no Retry), keyboard-aware. Same data source as web (`page_size=200`), payload unchanged (`interviewer` = user uuid, `null` when none); Edit preselects from the candidate and fills in id/designation once the list loads; people without a uuid are left out. No reporting-manager / recruiter / owner field is touched. Two existing tests that drove the old search/× interaction were updated for the new interaction only (payload assertions identical).

## 3. Leave Request cards (Part B)
`LeaveRequestCard` (see `employee_leave_request_cards.dart`): status accent + header (type, web status label — "Pending Manager Approval", "Pending HR Approval", Approved, Rejected, Cancelled), date range, prominent duration (`total_days`, so 0.5 shows as "0.5 days"), half-day / LOP / cancellation / document chips from real fields, the full reason, an **Approval flow** block with Manager (L1) always and HR (L2) only when assigned — each with its own decision, approver, remarks and date — footer with applied date and final decision, and a ≥44dp action that opens the existing detail sheet (approve / reject / cancel stay there, gated as before). Empty / no-match / error (Retry; 403 "Access denied") use the shared approvals states. 1 column on phones, 2 from 600dp. Additive change outside employees: nullable `totalDays` on `LeaveRequestEntity` (`days` unchanged).

## 4. Attendance timing — root cause
The parsing was correct (`clockIn`/`clockOut`). The faults were in the tab: (1) the calendar cells showed **no times at all** — they were reachable only by tapping a day into an alert dialog; (2) that dialog silently **omitted** a null clock-out instead of saying it was missing; (3) the backend's per-day `color` was never read and the status maps lacked **"Late (Excused)" and "Missing Clock Out"**, so those days had no colour or code; (4) the History row's late marker used an **invented 09:15 clock-time rule** instead of the server's status; (5) legend/colours differed from web (e.g. On Leave teal vs blue). Nothing was wrong with time zones: the backend sends wall-clock strings and the app never converted them (and still does not).

## 5. API field mapping (calendar day → UI)
`status` → status pill + cell code (P/L/LE/A/H/W/Ho/OL/!) · `color` → cell/pill colour (fallback: status table, then neutral) · `clockIn` → Clock In tile (— when null) · `clockOut` → Clock Out tile ("Not clocked out" when clock-in exists but clock-out is null; — otherwise) · `hours` → "Working hours" (only when present and not "—") · `note` → Note · `holiday_name` → Holiday · `lateJustificationStatus` → web's hint text. Weekly Off / Holiday hide the times (web NON_WORKING). Read-only: `canRegularize` / `canExplainLate` are not offered (web `readOnly`).

## 6. Timezone and overnight handling
Times are shown exactly as received ("22:00" → "06:05"); hours are the server's string, never recomputed. The API gives time-of-day only, so the clock-out's **date** cannot be shown or inferred — this is stated, not guessed (a backend `clock_out_date` would be needed to label "next day").

## 7. Calendar redesign
Month bar with 44dp arrows and a **Today** shortcut, 7-colour legend (web order), spaced rounded day cells with number + short code (clamped to 1.3× text; the details card follows the user's own text size), distinct selected (primary ring) and today states, "Attendance Details" card with labelled Clock In / Clock Out tiles, working hours, note and holiday rows; side-by-side with the grid from 720dp. Selection: today on the current month, none on another month (a day never carries over). Each month is its own request, so a late reply for a month the user left cannot appear. States: loading spinner (legend stays), error with Retry / Access denied, empty month note. Also fixed in the same tab: summary cells and stat cards no longer clip at large text (stack to 1–2 columns). The app bar is unchanged (the profile already follows the app's pattern).
